# What the user sees

What their page does at each step. SKILL.md holds what you do; read this when the user asks how the page behaves, or you need to explain it.

## Your cursor (step 2's `--agent`)

A cursor carrying your name and logo does your part on their page. It starts each round's page (step 3). The first time the user looks at the page, it works down their notes column, top to bottom, doing each thing still in view when it gets there (its bubble showing is enough): it types each of your messages where it goes, as a one-line typing bubble that grows into your words, and closes each thread the user answered in chat (step 7). A message that the ones above it push out of view as they grow in gets no visit. As the cursor leaves, everything else is there at once, on screen or further down. If the user scrolls, clicks or presses a key while it works, everything is there at once and the cursor fades. It also clicks in the states you cause on their notes bar: Received and Updating when their paste arrives (step 4), where it stays parked while you work, and Done (step 8). If the user wasn't looking when a state came, it clicks in only the state the bar has reached: Updating once Received's beat is over, Done when that's waiting, never the steps the user missed.

With helpers (step 2's `--helper` and `--owns`): on the page, each agent does only what it owns: a helper turns the round number and wipes in its own parts in its own colour, and you wipe the Outline and the rest and type your messages.

## Each round's opening (step 3)

The opening waits for the first time the user visits the round, even if the agent prepared it hours earlier. It counts as seen once it finishes or the user skips it by interacting with the page. Re-running notes or reloading a completed round does not play it again. Reloading an unfinished opening lets it play again. A new round gets its own opening.

The opening starts when the tab is visible and the browser window has focus. Switching away pauses the round-number change and wipes until the user returns. It shows as the user left it: on round one a blank page and Outline, on a later round the version before it, with their notes bar as the user left it: dark, reading the round before's number and Updating (green and Done if you'd called it done). That fades back to their light bar and the number rolls up to this round's. Then your cursor clicks the Outline, which wipes down from under its title bar to the new version's Outline (the bar itself never changes), then the page wipes down to the new version, then the cursor types each of your messages in view into their notes column (closed notes stay in their earlier round, with no stamping animation), top to bottom, and the rest are there as it leaves. The cursor moves on the moment each wipe reaches the bottom. With helpers (step 2), each agent has its own cursor and does only what it owns: a helper turns the round number, you wipe the Outline, each agent wipes its own parts of the page at its own moment (two can wipe at once), and you type the messages. Only round → Outline → page → notes waits; otherwise each comes and goes on its own. The round number and arrows sit in the Notes header and stay in place as the number rolls. On an earlier round, a double chevron right after Next jumps to the latest round. On the latest round, a Replay icon sits halfway between Next and the Notes toggle until the user copies; a copy or Done hides it. Received, Updating and Done take the same spot; a copy alone shows nothing there, since the Copy button already says it. Hover over, focus or tap the round label to see the date for that round. Replay wipes both columns back up and plays the opening again. It is absent under reduced motion.

## Edit and Highlight in framed mockups

Select words inside a local mockup to use the same menu as on the review page. Edit opens the words in place and shows what changed when you finish. Highlight marks words without starting a thread. The review page saves both, and ⌘Z takes back the last change. Copied edits name the mockup file and include the original and replacement wording.

## Threads and navigation

Every row in the notes column is a thread. A thread is open only while it waits on the user: an agent question or reply they haven't answered. Their own notes and edits are never open. Any emoji reaction, committed reply or picture response closes an agent message for the current round. A question also closes when the user leaves a note, reaction or picture on its part (SKILL.md step 7): its dot goes and it isn't carried, its Reply box stays, and deleting those notes opens it again. Drafts stay open, and old saved responses stay closed. A question first asked this round keeps its black New pill at the upper left, even after an answer; carried questions, replies and done marks get no New.

Small type and part headings are hidden. Each open thread has a purple dot at the upper right, on the first line of the thread so it adds no height (10 px across before the 1.11 scale is applied). Closing the thread bursts that dot out over 380 ms. Removing its last response pops it back in over 360 ms. Undo reverses the change. Under reduced motion, each state changes at once.

Outline badges show all threads for each part, with a purple dot when any are open. Both collapsed columns show the total thread count with the same any-open dot. Answering a thread changes its open state without reducing its total.

The expanded notes bar puts the thread arrows and count on the left. On the right, a purple dot follows the open count with a 10 px CSS gap. Clicking that legend goes to the first open thread; it is disabled at zero. The manual seeker reads `i of N threads`, or just `N threads` with none selected. Collapsed, it reads `i/N`, or `–/N` with none selected. Its arrows always visit every thread in page order and wrap, including when none are open. ⌥↑ / ⌥↓ do the same on the page or in a thread's Reply box.

Automatic advance visits only open threads. Committing a reply or reacting to an agent message moves to the next open thread in page order, including across tabs. The new panel and the notes fade in together when the tab changes. Past the last one down the page it wraps up to the first thread still open above. Once none is open it stops where it is and focuses Overall feedback. A draft does not advance. Reduced motion makes the move instant.

## Tabs

On a page with `role="tab"` tabs, one panel shows at a time. The Outline lists every tab, open or closed, as a level of its hierarchy: tabs at the top of the page are its top level, tabs in a section are that section's children, a tab inside a tab sits one level deeper, and what's in a tab is inset under its name. A click on a tab or on anything under it opens the tab. A thread on a part in a closed tab waits, unseen, and still counts: the arrows go through all threads in page order and open each tab they reach. Answering a thread opens another tab if it holds the next open thread. The open tab stays through a reload and a step between versions, in that browser tab. On a phone, opening the sheet with threads waiting only in closed tabs goes to the first of them.

The Overall feedback box shows all its words only while the cursor is in it. Out of it, it folds back to two lines with a short animation (none with reduced motion), so a long overall note never covers a thread.

## Reactions and narrow windows

In the notes column, reactions to the document hang off the bottom right corner of the quote, picture or part name. The sticker and its picker stay there whether the comment is empty, being typed or saved. Reactions to an agent message sit on that message's bottom right corner and never appear on the document. The done check on the left keeps the same vertical overlap as the reaction on the right. Document reactions use an empty section gutter, trying the right side then the left; they stay hidden when neither side fits.

When the notes column opens as a narrow overlay, the covered document scrollbar and connector lines hide. The left rail stays visible when it fits. In any window too small to show the page with both columns open (under about 1,108 px wide) or under 480 px tall, both columns go: the page fills the window, and a round button at the bottom right opens the notes as a sheet, with a dot while questions wait. The Outline and the Top and Bottom controls aren't shown there.

## When their paste arrives (step 4's `--received`)

Copy locks the whole round, including unanswered threads. Reply boxes disappear, and replies, reactions, and attachments wait for Unlock. Reloading keeps the round locked. Unanswered threads keep their open dots and counts. The agent's name bubble stays attached below-right, including while Updating. It can extend past the window edge.

What the user copied is already read-only from the moment the user copied it, each bubble the user sent kept as it was with a tick in its corner, two once this has run; within a few seconds of this run, your cursor flies in and clicks their notes bar, which turns dark and reads Received beside the round's number. After a beat it clicks again for Updating and stays parked beside it while you work (at most 30 minutes). Under reduced motion, or with their notes column shut, the states just appear. The user can still copy it again, or unlock it to keep editing or add notes.

## Replies and done marks (step 7)

When a note asks a question, the user sees their note in Notes, your answer under it, and a Reply box to answer back once. Longer explanations can sit in the page, linked from the reply. With `--gist '<note as copied>' "<short version>"`, their note shows its short version, in their own words, with See original underneath. That expands to all their words in place; See summary folds it back. This works on carried replies too; without a gist their note looks as before. Copy keeps their full words, even when folded. Gists carry with their thread. A run with `--gist` replaces the page's gists; a plain re-run keeps them.

Your answer is short. A blank line in `--reply`, `--again` or `--ask` makes separate bubbles in a pale wash of your violet, stacked in order; one paragraph stays one bubble. Links work in each, and React and the sticker sit on the last. The opening types in one bubble, then shows the paragraphs together. Copy joins your reply's paragraphs with spaces. The user's own notes and answers split the same way once saved or sent: a blank line in his words shows as one blue bubble a paragraph, on every round and earlier version, in a gist's See original, and on Overall from the round before. The receipt or done mark sits on his last bubble. His Comment and Reply boxes stay one box while he types, a click on any bubble opens the whole note in that box, and Copy keeps his words exactly as written.

The row counts as one thread and stays open until the user answers or the agent closes it. It gets no New pill, and Copy never reminds the user to answer it. A done mark marks the original note in the round where the user wrote it. When the user steps back with the version arrows, that row has the ✅, stays read-only and counts as a thread that isn't open. The new round has no duplicate row for it, and the opening never stamps it. A thread the user closes with an emoji reaction stays in its own round too, with the reaction, and isn't carried. The new round holds your replies and questions and carried unanswered threads. Done marks add no separate thread or count.
